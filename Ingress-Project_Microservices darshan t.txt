Step 1: Basic Setup
===================

1.1. Push the Code from Local to GitHub

Run these commands inside the project folder:

git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<your-username>/<repository-name>.git
git push -u origin main

Use Git Credential Manager, GitHub CLI, SSH, or a Personal Access Token when Git asks for authentication. Do not place the token directly in the remote URL.

1.2. Local Requirements

This project uses a local kind Kubernetes cluster.

Required tools:

- Git
- Docker Desktop or Docker Engine
- kind
- kubectl
- Helm

Verify them:

git --version
docker --version
kind version
kubectl version --client
helm version

===========================
Step 2: Tools Installation
===========================

2.1. Install Docker

Install Docker Desktop on Windows or macOS. On Ubuntu, create docker.sh with this content:

#!/bin/bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Run and verify it:

chmod +x docker.sh
./docker.sh
docker --version

On Ubuntu, allow the current user to run Docker without sudo:

sudo usermod -aG docker $USER

Log out and log in again after running the command.

2.2. Install kubectl and kind

Install kubectl and kind by following their official instructions for your operating system.

kubectl version --client
kind version

2.3. Install Helm

curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
chmod 700 get_helm.sh
./get_helm.sh
helm version

Step 3: Configure GitHub Actions
==========================================

GitHub Actions validates the application, builds the Docker image and pushes it to Docker Hub.

3.1. Create the Workflow

Create this file inside the GitHub repository:

.github/workflows/deploy.yml

The workflow automates:

- Source-code checkout
- Required-file validation
- Application build and testing
- Docker image build
- Docker image push to Docker Hub

Note: A GitHub-hosted runner cannot directly access a kind cluster running on your computer. Deploy to kind locally with kubectl or Argo CD. A self-hosted runner on the same computer is required only if direct automatic deployment is needed.

3.2. Configure GitHub Actions Secrets

Go to:

GitHub Repository -> Settings -> Secrets and variables -> Actions -> New repository secret

Add:

DOCKER_USERNAME
DOCKER_PASSWORD

Use a Docker Hub access token as DOCKER_PASSWORD.

3.3. Example GitHub Actions Workflow

name: Build and Push Docker Image

on:
  push:
    branches:
      - main
  workflow_dispatch:

env:
  IMAGE_NAME: ${{ secrets.DOCKER_USERNAME }}/techsolutions-app

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Source Code
        uses: actions/checkout@v4

      - name: Validate Application Files
        run: |
          test -f Dockerfile
          test -f nginx.conf
          test -f index.html
          echo "Required files are available"

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build and Push Docker Image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ${{ env.IMAGE_NAME }}:latest
            ${{ env.IMAGE_NAME }}:${{ github.sha }}

Step 4: Create the kind Cluster
=========================================

4.1. Create kind-config.yaml

kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4

nodes:
  - role: control-plane
    kubeadmConfigPatches:
      - |
        kind: InitConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            node-labels: "ingress-ready=true"
    extraPortMappings:
      - containerPort: 80
        hostPort: 80
        protocol: TCP
      - containerPort: 443
        hostPort: 443
        protocol: TCP
  - role: worker
  - role: worker

The mappings forward host ports 80 and 443 to the kind control-plane container so NGINX Ingress can receive local HTTP and HTTPS traffic.

4.2. Create and Verify the Cluster

kind create cluster --name techsolutions-cluster --config kind-config.yaml
kind get clusters
kubectl cluster-info --context kind-techsolutions-cluster
kubectl get nodes

4.3. Install NGINX Ingress Controller for kind

kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml

Wait until it is ready:

kubectl wait --namespace ingress-nginx \
  --for=condition=ready pod \
  --selector=app.kubernetes.io/component=controller \
  --timeout=180s

Verify it:

kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx

Access the application through localhost or a local hostname mapped to 127.0.0.1.

4.4. Delete the Cluster (Optional)

kind delete cluster --name techsolutions-cluster

===========================================
Step 5: Deploy the Application to kind
===========================================

5.1. Set the Image in deployment.yaml

image: <your-dockerhub-username>/techsolutions-app:latest
imagePullPolicy: Always

For a private Docker Hub repository, create an imagePullSecret first.

5.2. Apply and Verify the Manifests

kubectl apply -f k8s/
kubectl get deployments
kubectl get pods
kubectl get services
kubectl get ingress
kubectl describe ingress techsolutions-ingress

5.3. Access the Application

If the Ingress has no host rule, open:

http://localhost

If it uses techsolutions.local, add this to the hosts file:

127.0.0.1 techsolutions.local

Then open:

http://techsolutions.local

5.4. Deploy a New Image

After GitHub Actions pushes a new image:

kubectl rollout restart deployment/techsolutions-app
kubectl rollout status deployment/techsolutions-app

For reliable versioning, use the Git commit SHA image tag instead of latest.

=========================================
Step 6: Monitoring the kind Cluster
=========================================

Install Prometheus and Grafana inside kind using Helm. A separate monitoring VM is not required.

6.1. Install kube-prometheus-stack

helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
kubectl create namespace monitoring
helm install monitoring prometheus-community/kube-prometheus-stack -n monitoring
kubectl get pods -n monitoring

6.2. Access Prometheus

kubectl port-forward -n monitoring svc/monitoring-kube-prometheus-prometheus 9090:9090

Open http://localhost:9090 and press Ctrl+C to stop port forwarding.

6.3. Access Grafana

Get the admin password:

kubectl get secret -n monitoring monitoring-grafana -o jsonpath="{.data.admin-password}" | base64 --decode

Forward the service:

kubectl port-forward -n monitoring svc/monitoring-grafana 3000:80

Open http://localhost:3000

Username: admin
Password: Use the password returned by the secret command.

The stack supplies Kubernetes and node dashboards.

Step 7: Argo CD Deployment (Optional)
=========================================

7.1. Install Argo CD

helm repo add argo https://argoproj.github.io/argo-helm
helm repo update
kubectl create namespace argocd
helm install argocd argo/argo-cd --namespace argocd
kubectl get pods -n argocd

7.2. Access Argo CD Locally

Keep argocd-server as ClusterIP. A cloud LoadBalancer is not required for kind.

kubectl port-forward svc/argocd-server -n argocd 8080:443

Open https://localhost:8080

Username: admin

Get the initial password:

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d

7.3. GitOps Flow

1. Push application code to GitHub.
2. GitHub Actions builds and pushes the image to Docker Hub.
3. Update the image tag in the Kubernetes manifest in GitHub.
4. Argo CD detects the manifest change.
5. Argo CD synchronizes the application into the local kind cluster.

The kind cluster and Argo CD are available only while Docker and the local cluster are running.

=========================================
Final Project Flow
=========================================

Developer -> GitHub -> GitHub Actions -> Docker Hub
                                      -> Kubernetes manifest update
                                      -> Argo CD
                                      -> Local kind cluster
                                      -> NGINX Ingress
                                      -> Application

Prometheus and Grafana monitor the Kubernetes cluster and application locally.
